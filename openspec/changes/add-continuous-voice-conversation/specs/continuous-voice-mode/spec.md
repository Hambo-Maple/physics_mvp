## ADDED Requirements

### Requirement: 连续语音对话模式开关
系统 SHALL 提供连续语音对话模式的开关按钮，允许用户启动和停止连续语音对话循环。

#### Scenario: 用户启动连续语音对话模式
- **WHEN** 用户点击"连续对话"按钮
- **THEN** 系统进入连续语音模式，按钮变为激活状态（墨绿色背景、白色文字、闪烁动画）
- **AND** 顶部状态栏显示"正在连续语音对话中..."
- **AND** 系统开始持续监听麦克风输入

#### Scenario: 用户停止连续语音对话模式
- **WHEN** 用户在连续模式下再次点击"连续对话"按钮
- **THEN** 系统停止连续语音模式，按钮恢复默认状态
- **AND** 顶部状态栏消失
- **AND** 系统停止监听麦克风，释放所有音频资源

#### Scenario: 连续模式按钮位置
- **WHEN** 用户查看对话输入区
- **THEN** "连续对话"按钮位于"语音输入"按钮右侧、"发送"按钮左侧
- **AND** 按钮宽度与其他按钮保持一致

### Requirement: 自动静音检测与录音控制
系统 SHALL 在连续语音模式下自动检测用户语音活动，当检测到声音时开始录音，当检测到声音后的 1.5 秒静音时自动停止录音。如果用户一直沉默未说话，系统保持录音状态等待用户开始说话。

#### Scenario: 检测到用户开始说话
- **WHEN** 连续模式监听中，麦克风音量超过阈值（RMS >= 5）
- **THEN** 系统自动开始录音
- **AND** 状态栏更新为"正在录音..."
- **AND** 波形动画开始显示音量变化
- **AND** 标记已检测到声音，开始监测后续静音

#### Scenario: 检测到用户停止说话
- **WHEN** 录音过程中检测到声音后，麦克风音量持续低于阈值（RMS < 5）达到 1.5 秒
- **THEN** 系统自动停止录音
- **AND** 状态栏更新为"正在识别..."
- **AND** 自动调用语音识别接口

#### Scenario: 用户一直沉默
- **WHEN** 连续模式监听中，用户一直未说话（音量始终低于阈值）
- **THEN** 系统保持录音状态，不触发静音检测
- **AND** 继续等待用户开始说话
- **AND** 不会因为长时间静音而自动停止

#### Scenario: 静音检测阈值配置
- **WHEN** 系统初始化静音检测功能
- **THEN** 音量阈值设置为 RMS < 5（0-255 范围）
- **AND** 静音时长阈值设置为 1.5 秒（仅在检测到声音后生效）
- **AND** 使用 Web Audio API 的 AnalyserNode 进行实时音量分析

### Requirement: 自动语音识别与消息发送
系统 SHALL 在连续语音模式下自动将录音发送到语音识别服务，识别成功后自动发送消息到 AI 对话系统。

#### Scenario: 自动识别并发送消息
- **WHEN** 连续模式下录音停止
- **THEN** 系统自动调用百度语音识别 API
- **AND** 识别成功后自动填充输入框
- **AND** 自动触发发送消息逻辑（调用 sendMessage 函数）
- **AND** 无需用户手动点击发送按钮

#### Scenario: 识别失败后继续监听
- **WHEN** 连续模式下语音识别失败（如未识别到内容、网络错误）
- **THEN** 系统显示 Toast 错误提示
- **AND** 自动继续监听下一段语音
- **AND** 不中断连续语音循环

#### Scenario: 识别到的文本触发参数解析
- **WHEN** 连续模式下识别到的文本包含参数指令（如"初速度改为20"）
- **THEN** 系统自动解析参数并更新可视化
- **AND** AI 回复中包含参数确认信息
- **AND** 继续监听下一段语音

### Requirement: AI 回答完成后自动继续监听
系统 SHALL 在连续语音模式下等待 AI 流式输出完成后，自动开始监听下一段用户语音。

#### Scenario: 等待 AI 回答完成
- **WHEN** 连续模式下消息发送后，AI 开始流式输出
- **THEN** 系统进入"等待 AI"状态
- **AND** 状态栏显示"AI 正在回答..."
- **AND** 暂停麦克风监听，不接受新的语音输入

#### Scenario: AI 回答完成后继续监听
- **WHEN** AI 流式输出完成（state.isGenerating 变为 false）
- **THEN** 系统自动恢复监听状态
- **AND** 状态栏更新为"正在连续语音对话中..."
- **AND** 开始监听下一段用户语音

#### Scenario: 可视化参数自动更新
- **WHEN** AI 回答中包含可视化触发标记（如 [TRIGGER:PROJECTILE]）
- **THEN** 系统自动更新可视化类型
- **AND** 平抛运动参数自动应用
- **AND** 继续监听下一段语音

### Requirement: 连续模式视觉反馈 - 状态栏
系统 SHALL 在连续语音模式下显示顶部状态栏，实时展示当前状态。

#### Scenario: 状态栏显示与隐藏
- **WHEN** 用户启动连续语音模式
- **THEN** 在 ChatBox 标题栏下方显示状态栏
- **AND** 状态栏高度为 32px，墨绿色背景（#006644），白色文字
- **AND** 用户停止连续模式时状态栏消失

#### Scenario: 状态栏文本更新
- **WHEN** 连续模式处于不同阶段
- **THEN** 状态栏显示对应文本：
  - 监听中："正在连续语音对话中..."
  - 录音中："正在录音..."
  - 识别中："正在识别..."
  - 等待 AI："AI 正在回答..."

### Requirement: 连续模式视觉反馈 - 按钮闪烁
系统 SHALL 在连续语音模式激活时，使"连续对话"按钮产生闪烁动画效果。

#### Scenario: 按钮激活状态样式
- **WHEN** 连续语音模式开启
- **THEN** "连续对话"按钮背景色变为墨绿色（#006644）
- **AND** 按钮文字变为白色
- **AND** 按钮产生闪烁动画（1.5 秒周期，透明度在 1.0 和 0.7 之间变化）

#### Scenario: 按钮默认状态样式
- **WHEN** 连续语音模式关闭
- **THEN** "连续对话"按钮背景色为浅灰色（#f5f5f5）
- **AND** 按钮文字为深灰色（#333）
- **AND** 无闪烁动画

### Requirement: 连续模式视觉反馈 - 麦克风波形动画
系统 SHALL 在连续语音模式下显示实时麦克风波形动画，反映当前音量变化。

#### Scenario: 波形动画显示位置
- **WHEN** 连续语音模式开启
- **THEN** 在状态栏右侧显示波形动画
- **AND** 波形由 3-5 个竖条组成，每个竖条宽度 4px，间距 4px

#### Scenario: 波形动画随音量变化
- **WHEN** 麦克风接收到音频输入
- **THEN** 竖条高度根据实时音量变化（范围 10-30px）
- **AND** 使用 Web Audio API 的 AnalyserNode 获取音量数据
- **AND** 动画更新频率为 60fps（使用 requestAnimationFrame）

#### Scenario: 波形动画样式
- **WHEN** 波形动画渲染
- **THEN** 竖条颜色为白色
- **AND** 竖条圆角为 2px
- **AND** 静音时竖条高度保持最小值（10px）

### Requirement: 连续模式与单次语音输入互斥
系统 SHALL 确保连续语音模式与单次语音输入功能互斥，同一时间只能有一种模式激活。

#### Scenario: 连续模式开启时禁用单次语音
- **WHEN** 用户启动连续语音模式
- **THEN** "语音输入"按钮被禁用（disabled 状态）
- **AND** 输入框被禁用
- **AND** 用户无法点击"语音输入"按钮

#### Scenario: 单次语音进行中禁用连续模式
- **WHEN** 用户正在进行单次语音输入（录音或识别中）
- **THEN** "连续对话"按钮被禁用
- **AND** 用户无法启动连续语音模式

#### Scenario: 连续模式停止后恢复单次语音
- **WHEN** 用户停止连续语音模式
- **THEN** "语音输入"按钮恢复可用状态
- **AND** 输入框恢复可用状态

### Requirement: 连续模式资源管理与清理
系统 SHALL 在连续语音模式停止时正确释放所有音频资源，防止内存泄漏。

#### Scenario: 停止连续模式时清理资源
- **WHEN** 用户停止连续语音模式
- **THEN** 停止所有 MediaRecorder 实例
- **AND** 停止所有音频轨道（调用 track.stop()）
- **AND** 关闭 AudioContext（调用 audioContext.close()）
- **AND** 清除所有定时器和 requestAnimationFrame 回调

#### Scenario: 每次录音结束后清理临时资源
- **WHEN** 连续模式下单次录音结束
- **THEN** 清理当前 MediaRecorder 实例
- **AND** 停止当前音频轨道
- **AND** 清空音频数据缓存（audioChunks）

### Requirement: 连续模式错误处理与恢复
系统 SHALL 在连续语音模式下优雅处理各类错误，确保用户体验不中断。

#### Scenario: 麦克风权限丢失时停止连续模式
- **WHEN** 连续模式运行中，麦克风权限被撤销
- **THEN** 系统自动停止连续语音模式
- **AND** 显示 Toast 错误提示"麦克风权限丢失"
- **AND** 按钮恢复默认状态，状态栏消失

#### Scenario: 网络错误时继续监听
- **WHEN** 连续模式下语音识别 API 调用失败（网络错误）
- **THEN** 系统显示 Toast 错误提示"识别失败，请稍后重试"
- **AND** 自动继续监听下一段语音
- **AND** 不中断连续语音循环

#### Scenario: AI 服务错误时继续监听
- **WHEN** 连续模式下 AI 对话服务返回错误
- **THEN** 系统显示 AI 错误消息
- **AND** 自动继续监听下一段语音
- **AND** 不中断连续语音循环
